# astrbot_plugin_error_restart_chat

限制 LLM 单次回复的字数。当模型（尤其在长上下文时）输出超长的胡言乱语时，插件会自动用**与原请求完全相同的配置**（系统提示词、上下文、提示词、图片、模型等）重新生成一次；超限的坏回复**不会写入会话历史**，也不会发送到聊天平台。

## 功能

- 在 WebUI 插件配置中设置单次回复的最大字数（默认 500，设为 0 可禁用）；
- 回复超限时自动重新生成，可配置最大重试次数（默认 2 次）；
- 重试时默认与原请求完全一致（可通过「重试附加提醒」选择性地给模型加一句控制字数的提醒）；
- 超限的坏回复不进入会话历史 —— 后续对话不会"记得"这段胡话；
- 重试全部失败后，可选择丢弃回复（发送提示语，默认行为）或照常发送原回复。

## 环境要求

- **AstrBot >= v4.24.1**（本插件使用了 v4.24.1 引入的 `on_agent_done` 钩子来修正会话历史，更低版本无法加载本插件）。

## 安装

将本目录放入 `AstrBot/data/plugins/` 下（或在 WebUI 插件页从本地导入），重载插件即可。无第三方依赖。

## 配置项

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| `max_output_chars` | 单次回复最大字数（字符数），0 为禁用 | 500 |
| `max_retries` | 超限后重新生成的最大尝试次数 | 2 |
| `retry_hint` | 重试时附加到原提示词末尾的提醒，留空表示与原请求完全一致 | 空 |
| `on_fail` | 重试全部失败后的处理：`discard` 丢弃 / `keep` 照常发送 | `discard` |
| `fail_notice` | 丢弃回复时发送的提示语 | ⚠️ 本次回复超出字数限制…… |

## 工作原理

1. `on_llm_request` 钩子在调用模型前保存一份请求快照（优先级最低，保证拿到其他插件修改后的最终配置）；
2. `on_llm_response` 钩子检查回复纯文本长度（优先级最高，保证在其他响应处理插件之前检测原始文本），超限则用快照重放请求，成功后直接替换本次响应内容 —— 用户看到、以及后续插件处理的都是修正后的回复；
3. `on_agent_done` 钩子同步修正 AstrBot 即将写入数据库的会话历史（超限回复在落库前被替换或标记跳过）；重试全部失败时清空响应并终止事件传播，核心既不发送也不落库。

## 注意事项

- 面向 AstrBot v4 内置 Agent 流程（本地 runner）；使用第三方 Agent runner（dify/coze 等）时本插件不生效。
- 函数工具调用轮次（模型决定调用工具的那几轮）不做检测，只检测最终文本回复，因此不影响 Agent / 插件工具的正常运行。
- 开启流式输出（分段回复）时，超限原文已经实时发出、无法撤回；插件仍会重试并补发修正后的回复，同时保证历史记录干净。若希望本插件严格"只见修正后回复"，请关闭流式输出。
- 若某个模型在相同请求下反复输出超长内容，可在 `retry_hint` 中加一句字数提醒，可显著提高重试成功率。
